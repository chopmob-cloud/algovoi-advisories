# AlgoVoi security advisories

Public advisories for vulnerabilities found in AlgoVoi software and services.

We publish here rather than in the affected code repository for one reason: most of the affected services are private source, so there is no public repository to file against. A dedicated repository gives researchers and users a stable, citable URL that does not move when a product repository is renamed.

## Reporting a vulnerability

Email security@algovoi.co.uk. If you prefer a public channel, open an issue on any of our public repositories and ask for a private contact route.

We will acknowledge within two working days, tell you what we have reproduced, and give you a date for the fix. We will not publish an advisory until you have seen the text.

## Credit policy

We credit researchers by name or handle, whichever you prefer, with a link if you want one. Tell us at the time of the report:

1. The name or handle to use.
2. Whether you want it linked, and to where.
3. Whether you want a name alongside a handle, or the handle alone.
4. Any wording you would prefer we use or avoid when describing how the issue was found.

We do not publish a credit until the researcher confirms the wording. If a researcher asks not to be named, the advisory says so and names nobody.

## What an advisory contains

Each file states what was wrong, what the impact was, how it was found, the timeline in UTC, what changed, and how a reader can verify the fix themselves. Where we did not demonstrate something, the advisory says that rather than leaving it implied.

## Scope

Advisories concern AlgoVoi operated services and first party software. Third party dependency advisories are referenced by link rather than republished.
